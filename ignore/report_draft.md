# 2023—2026 年大语言模型后训练的发展路径与方法比较

## 摘要

预训练让语言模型获得了知识和生成能力，但模型仍可能不遵循指令、回答不符合人类偏好，或在数学等任务上缺少可靠的推理过程。后训练（post-training）就是在预训练模型之后，利用指令、偏好、规则或可验证结果继续优化模型。本文不按论文逐篇罗列，而是从**优化目标、数据形式、奖励来源、训练成本和可验证性**五个维度整理 2023—2026 年后训练方法。发展路线可以概括为：从“模仿高质量答案”的 SFT，发展到“用奖励进行在线策略优化”的 RLHF/PPO，再发展到“直接利用偏好数据”的 DPO、KTO、ORPO 等方法，随后进一步转向“可验证奖励、过程奖励和推理时计算扩展”。本文还分析一个 NumPy GridWorld 教学实验，将奖励模型、PPO 和 DPO 的思想与实际代码对应起来，并讨论其与真实 LLM 训练之间的差距。

**关键词：** 大语言模型；后训练；SFT；RLHF；PPO；DPO；GRPO；可验证奖励

## 1. 问题与比较框架

本文把后训练看成一个统一问题：给定输入 \(x\)，模型生成回答 \(y\)，希望新模型既保留预训练能力，又更符合某种目标。这个目标可能是“像示范答案”，也可能是“人类更喜欢”，还可能是“答案经过程序验证”。

比较方法时，不能只问“哪个分数最高”，还应同时问：

1. **目标是什么：** 模仿、偏好、规则遵循，还是推理正确性？
2. **数据是什么：** 单个示范、chosen/rejected 偏好对、二值标签，还是可自动验证的问题与答案？
3. **奖励从哪里来：** 人类、AI 反馈、奖励模型、规则程序或答案验证器？
4. **更新如何完成：** 交叉熵、分类损失、在线 RL，还是组内相对比较？
5. **失败如何发现：** 人工评测、自动指标、约束检查，还是多次采样和过程审计？

## 2. 后训练目标的变化

### 2.1 从“会回答”到“按要求回答”

SFT（Supervised Fine-Tuning）使用输入—标准回答对，最小化回答的交叉熵。它实现简单、训练稳定，适合学习格式、角色、工具调用和基本指令，但答案质量依赖标注数据，模型也可能只学到表面模板。

### 2.2 从“模仿答案”到“符合偏好”

RLHF 通常先收集多个回答的排序，训练奖励模型，再使用 PPO 等强化学习方法让策略获得更高奖励，同时通过 KL 惩罚限制模型偏离参考模型。它能表达“两个答案哪个更好”，但需要奖励模型、在线采样、价值模型和较多超参数，训练链路复杂。

### 2.3 从“人类偏好”到“任务结果可验证”

开放式对话很难定义唯一正确答案，而数学、代码、形式证明和工具调用常常可以由程序检查。这样奖励可以从主观偏好转向结果验证。DeepSeekMath 将 GRPO 描述为 PPO 的变体，用同一问题生成的一组答案计算相对优势，从而减少 PPO 对价值模型和显存的需求。2025 年 DeepSeek-R1 进一步展示了大规模强化学习对推理行为的影响，但这类方法仍需要高质量问题、验证器和防止奖励投机的评测。

## 3. 方法分类与发展路线

| 类别 | 代表方法 | 训练信号 | 是否在线采样 | 主要优点 | 主要风险 |
|---|---|---|---|---|---|
| 监督模仿 | SFT | 示范答案 token | 否 | 稳定、实现简单 | 受示范质量限制 |
| 奖励模型 + 在线 RL | RLHF + PPO | 排序训练出的奖励 | 是 | 能直接优化复杂偏好 | 链路复杂、奖励黑客、训练不稳定 |
| 直接偏好优化 | DPO | chosen/rejected 对 | 否 | 不需要单独在线 RL，代码较简单 | 偏好数据偏差会直接进入模型 |
| 二值或单边反馈 | KTO | desirable/undesirable 标签 | 否 | 不一定需要成对偏好 | 正负样本比例和参考点影响较大 |
| 单阶段偏好 SFT | ORPO | SFT 交叉熵 + odds-ratio 惩罚 | 否 | 不需要额外参考模型，流程短 | 目标耦合，调参和数据质量仍重要 |
| 组内相对 RL | GRPO | 同一问题多答案的相对奖励 | 是 | 可省略或弱化价值模型 | 需要可靠验证器和足够候选 |
| 可验证奖励 | verifier/RL、RLAIF | 程序、规则或 AI 评审 | 通常是 | 反馈更客观、适合数学代码 | 验证器覆盖范围有限，可能被钻漏洞 |
| 过程监督 | PRM、过程奖励 | 中间步骤或轨迹 | 通常是 | 能指导长推理 | 标注昂贵，错误步骤的定义困难 |

### 3.1 DPO：把 RLHF 的一部分变成分类损失

DPO 的核心是用参考模型的 log probability 构造偏好差异：

\[
\mathcal{L}_{DPO}=-\log\sigma\left(\beta[
(\log\pi_\theta(y_w|x)-\log\pi_{\mathrm{ref}}(y_w|x))
-(\log\pi_\theta(y_l|x)-\log\pi_{\mathrm{ref}}(y_l|x))]\right).
\]

它仍然使用偏好数据，但不显式训练奖励模型，也不需要像 PPO 那样不断从当前策略采样。DPO 论文报告其在多个任务上达到不低于 PPO-RLHF 的效果，并强调实现和调参更简单。应注意，DPO 不是“没有奖励”：偏好排序仍然是奖励信息的间接来源。

### 3.2 KTO 与 ORPO：降低数据和流程门槛

KTO 只需要一个回答是否 desirable 的信号，而不是严格的 chosen/rejected 成对数据。ORPO 把偏好惩罚和 SFT 合并，不再需要额外参考模型。它们体现出一个趋势：后训练不一定要采用完整的 RLHF 流水线，而是尝试把偏好信息直接放进更稳定的损失函数。

### 3.3 PPO 与 GRPO：重新重视在线反馈

PPO 通过限制新旧策略概率比值，避免一次更新过大。它适合策略必须不断与环境交互、奖励只有在生成后才能得到的任务，但在语言模型中一次 rollout 成本很高。GRPO 用同一问题的一组回答的奖励均值和方差构造相对优势，减少价值模型的开销，因此更适合可验证数学和代码任务。代价是：组内比较只能告诉模型“相对谁更好”，不能自动保证验证器本身正确。

## 4. 2023—2026 的发展脉络

- **2023：DPO 改变了偏好优化的工程取舍。** 重点从“先训练奖励模型、再在线 RL”转向直接用偏好对优化策略。
- **2024：方法分化。** KTO 探索单边二值反馈，ORPO 探索无参考模型的单阶段偏好优化，DeepSeekMath 将 GRPO 用于数学推理；研究重点从“是否对齐”扩展到“如何减少显存、采样和标注成本”。
- **2025：推理和可验证奖励成为中心。** DeepSeek-R1 等工作说明，强化学习可以诱导更长的推理行为；同时，s1 等工作表明少量高质量推理轨迹与推理时预算控制也能带来收益。因此“训练时优化”和“推理时扩展”开始结合。
- **截至 2026：更值得关注的方向。** 方向不应只追求更大的奖励，而应同时提高验证器覆盖率、过程可解释性、跨任务泛化、数据效率和安全评测。对开放式对话，DPO/KTO/ORPO 仍然方便；对数学、代码、工具使用，GRPO、过程奖励和可验证奖励更有潜力。

## 5. 从论文公式到训练程序

将论文方法写成程序时，可以按以下五层拆解：

1. **数据层：** 明确样本是 `(prompt, answer)`、`(chosen, rejected)`、二值标签，还是 `(question, candidates, rewards)`。
2. **评分层：** 实现人工偏好、奖励模型、规则检查器或答案验证器，并记录评分范围。
3. **目标层：** 实现交叉熵、Bradley–Terry、DPO loss、PPO clipped objective 或组内优势。
4. **更新层：** 记录参考策略、旧策略概率、KL 或 clip 范围，防止把不同算法的变量混用。
5. **评估层：** 至少同时报告代理奖励、真实任务指标、成功率和失败类型，避免只报告训练目标。

## 6. GridWorld 实践

### 6.1 已有 Mini-RLHF 链路

`RL/lab-gridworld-starter.ipynb` 使用 5×5 GridWorld，环境中有起点、终点、墙和陷阱。已有实验依次完成：

1. 用 Q-learning 得到行为策略；
2. 收集不包含陷阱轨迹的偏好数据；
3. 用 Bradley–Terry 训练线性奖励模型；
4. 用学习到的代理奖励重新训练 Q-learning；
5. 同时比较奖励模型分数和环境真实回报。

执行 notebook 的结果显示，基线策略真实回报为 **9.10**，而在偏好数据存在盲区时，RLHF 策略真实回报为 **-0.40**，并稳定踩中陷阱；这说明代理奖励升高不等于真实目标变好，是 reward hacking 的一个小型可复现实例。加入少量陷阱轨迹后，奖励模型学到了负面的陷阱特征，结果明显改善。这与 LLM 后训练中的“数据覆盖和奖励模型外推”问题直接对应。

### 6.2 新增 PPO 教学实现

notebook 末尾新增了 NumPy 表格版 PPO。它包含：

- 按当前策略采样轨迹；
- 计算折扣回报和优势；
- 用概率比值和 clip 范围限制策略更新；
- 用状态价值表拟合回报。

该实现的价值是展示 PPO 的变量关系，而不是追求与 TRL、DeepSpeed 或真实 LLM 的工程性能。默认一次运行的贪心策略真实回报为 **-3.00**，说明从随机表格策略开始时，稀疏奖励和小环境仍会导致训练不稳定，需要更多种子、更新轮数、优势归一化或更合适的初始化。报告中应把它作为“算法机制验证”，不要把单次结果写成 PPO 劣于 DPO 的结论。

### 6.3 新增 DPO 教学实现

notebook 还新增了简化的轨迹级 DPO：

- 用 Q-learning 行为策略采集轨迹；
- 根据真实环境回报构造 chosen/rejected 轨迹对；
- 以 Q-learning 策略的 logits 作为参考策略；
- 优化 chosen 相对于 rejected 的 log-prob 差异。

这不是语言模型 DPO 的完整实现，因为 GridWorld 的“回答”只是动作序列，没有 tokenizer、Transformer 或 token-level log probability。它只演示 DPO 的结构：**离线偏好对 + 参考策略 + 相对 log-prob 优化**。默认结果也不应与真实 LLM 基准比较。

## 7. 局限与未来方向

第一，GridWorld 的状态和动作很小，不能代表语言模型的长文本分布、上下文建模或 token-level credit assignment。第二，实验偏好标签由环境真实回报生成，而真实 RLHF 的标签来自人类或 AI 评审。第三，实验规模小、随机种子少，不能据此排列 PPO、DPO、GRPO 的绝对优劣。

更有价值的后续实验是：

1. 为 PPO 增加优势归一化、熵正则和多随机种子统计；
2. 将 DPO 的轨迹对拆成动作级或片段级偏好，观察偏好粒度的影响；
3. 比较“缺少陷阱样本”和“加入陷阱样本”时奖励模型的泛化；
4. 对每种方法同时报告代理目标和真实回报；
5. 在代码或数学小任务上使用真正的 verifier，测试规则奖励是否被投机。

## 8. 结论

2023—2026 年后训练的主线不是简单地从一种算法替换为另一种算法，而是反馈来源和优化位置不断变化：SFT 解决“模仿什么”，RLHF/PPO 解决“如何在线追求偏好”，DPO/KTO/ORPO 解决“如何用更简单的损失利用偏好”，GRPO 和 verifier-based RL 解决“如何利用可验证结果推动推理”。未来最有潜力的系统应将高质量数据、可靠验证器、过程监督、低成本偏好优化和严格的真实任务评估结合起来。
